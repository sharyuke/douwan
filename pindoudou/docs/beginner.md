### 预览图为什么以前很小（第 ② 步 / 第 ③ 步）

画布的行内尺寸是 `lib/render.js` 的 `prepareCanvas` 写死的 px（1 格 = 1 CSS px），
所以 234×312 的图纸画出来只有 234×312 px，预览区却有好几百像素宽 —— 图缩在中间一小块。

2026-10-26 改成：渲染分辨率 `max-size` 520 → 640（画布固有尺寸翻倍），再用 CSS
让画布按可用区域等比放大（`width/height: auto !important` + `max-width/max-height: 100%`）。
预览区高度用 `clamp(360px, 60vh, 660px)`（拼豆效果 / 对比两个页签），原图页签按原图自然尺寸。
第 ③ 步「拿走图纸」的成果预览同样处理：`max-size` 420 → 640，预览框（`.bexp__art`）
在 ≥781px 时高度定成 `clamp(360px, 60vh, 660px)`、网格行 `minmax(0,1fr)`，
画布用同一套「auto + max 约束」等比撑满。
手机端（≤780px）走的是另一套：一屏工作台里预览框用 `clamp(110px,24vh,210px)`（见 §2.1）。

踩过的坑（改这块必看）：

- 行内样式的优先级高于样式表，压它只能用 `!important`；
- **不能**用 `height:100%` 撑画布：画布的固有高度比容器高时，网格行的基准尺寸被它顶住，
  百分比解析不出来，画布直接溢出容器（实测 624px 画布在 512px 容器里溢出 112px）；
- 能用的写法是「auto + max 约束」（max 约束会等比缩放，比例不会变形），
  并且**外层网格的行要写成 `minmax(0,1fr)`**：行高一旦由内容决定，里面的
  `max-height:100%` 就解析不出来。

视觉全部复用线上现有令牌：品牌黄 `#FFD62E` 主按钮、奶油白 `#FFF9F1` 背景、圆角、粗线条像素风图标
（`PixelIcon`）、标语「所爱皆可拼，万物皆可造」。**没有新建图标库，没有贴原型图当背景**，
也没有 VIP / 付费 / 卡密 / 追星应援字样。

## 2.1 手机端一屏工作台（2026-10-26 晚）

> 需求：`Z:\拼豆\新手简化版\新手2.0\03_详细需求文档_PRD.md`、
> `DouWan_Visual_Guide.md`、`DouWan_Grok_Commands.md`
> **只改手机端（≤780px）的布局**：Logo、配色、字体、步骤条、底部导航、像素图标、
> 按钮样式、卡片圆角阴影、业务逻辑全部保留；平板 / 电脑 / 专业版一个字没动。

### 版面分层（由上到下）

```
顶栏（Logo + 新手/专业切换，不改）
步骤条（三段压扁成一行，不改配色）
┌ 中央单步骤工作区（flex:1，min-height:0，overflow:hidden）┐
│ ① 双入口 + 素材卡片内部滚动                          │
│ ② 大画布 + 尺寸/颜色紧凑区                            │
│ ③ 预览 + 2 列摘要 + 材料清单（明细进抽屉）            │
└──────────────────────────────────────────────────────┘
底部本步主按钮（常显，在标签栏上方，不遮挡画布）
底部四导航（不改）
```

### 关键做法

| 点 | 做法 |
| --- | --- |
| 一屏 | `.bview` 锁高 `calc(100dvh - 顶栏 - 86px - 安全区 - 键盘高度)` + `overflow:hidden`；整页不再往下长，滚动只发生在中间那一步里 |
| 底部主按钮 | 从 `position:fixed` 浮层改成**容器里的一格**（`flex:0 0 auto`）⇒ 永远在标签栏上方，也永远不会盖住上面的内容 |
| 键盘弹起 | `visualViewport` 量出被键盘吃掉的高度写进 `--kb`，容器高度再减掉它（`100dvh` 本身不跟键盘缩） |
| 画布 | 预览区 `flex:1`，画布按容器等比缩放（`width/height:auto !important` + `max-width/height:100%`），不压扁也不溢出 |
| 第 ② 步画布大小 | 预览格给 `min-height: clamp(250px, 40dvh, 430px)` —— 照着**专业版工作台手机端画布**的量级定的（专业版实测 186 / 260 / 338 px @ 360 / 390 / 430；新手版落在 164 / 251 / 286 px）。矮屏（≤700px 高）再让出 6px 给参数区 |
| 参数区 | 滑块与档位压到画布下方；数据卡改成「标签 · 数值」一行；颜色三档排一行；**画布优先之后参数区一定放不下全部内容，它自己滚**（矮屏去掉颜色三档按钮的第二行说明，保证滚到底能整块看见） |
| 素材列表 | 卡片区独立滚动（`.bsel__libScroll`），搜索与分类固定在顶上 |
| 材料清单 | 页面上只留摘要 + 前若干项 +「查看全部 N 种」，明细进**底部抽屉**（可搜索、可滚动、关闭不丢状态） |
| 极矮屏 | 360×640 这类屏允许「中部局部滚动」，但步骤条、底部 CTA、标签栏不离屏，面包屑让位给画布 |

### 验收

`scripts/verify-beginner.cjs` 扩到 **手机三档（360×640 / 390×844 / 430×932）+ 平板 + 电脑，
212 项断言**：整页不滚动、画布完整落在预览框里、**第 ② 步画布 ≥ 视口 25%（专业版画布占 29~36%）**、
参数区自己滚且滚到底能完整看到颜色三档、底部 CTA 在标签栏之上、摘要 6 个字段压成 2 列、
材料抽屉能开能关、素材列表自己滚。

## 3. 模式切换与两条保护

| 方向 | 行为 |
| --- | --- |
| 新手 → 专业 | 只换界面，图纸内容、尺寸、色号、素材来源、作品 ID 一个都不动 |
| 专业 → 新手 | 若这张图被**逐颗改过**（`manualEdited`），先弹确认层说明「不会自动重画」，确认后停在第 ③ 步「获取图纸」，不按新手默认参数重画 |
| 新手改参数 | 会重算图纸 → 若图被手改过，弹「**保留当前修改** / **另存一个版本并继续**」两条路：前者什么都不做，后者先把当前存成作品再按新参数重算 |

模式状态**不写 localStorage**：记住上次模式就等于「打开就回专业版」。
首页（`/`）是宣传页，不参与模式同步；操作台 `/create` 刷新仍在操作台，专业工作台 `/editor` 刷新仍在专业版。

## 9. 遗留项与注意事项

1. **后端分支已合并**：SEO V3.0（关键词管理）原本只在 `feat/seo-platform` 分支上，
   2026-10-25 晚上的「排除名单」发布把线上二进制换成了不含 V3.0 的 master 版本，
   导致 `/colors/` 服务端渲染 404、V3.0 关键词接口 404。本次已把两条分支合并
   （`douwan-api` 的 `feat/seo-v3-merge`）并重新发布，两个接口都恢复正常。
2. **素材 SEO 文案已统一**：线上 85 条素材的标题统一为「名称拼豆图纸｜免费拼豆素材 - 豆玩」
   （原来 11 条是新上传的素材、用了旧格式「…素材免费下载 - 豆玩」），由后台「重新生成自动文案」统一重算。
3. **旧链接 `/home` 只剩跳转**：重定向到 `/`（首页已恢复），不再单独渲染页面；
   它仍在 `APP_ROUTES` 里，所以服务端给它的响应是 `noindex`。
4. **操作台不在 sitemap 里**：`/create` 是应用内页面（`noindex`），不与首页抢同一个主题的权重；
   首页 `/` 沿用原首页的 canonical 与关键词定位。
5. **素材区只显示免费素材**：操作台过滤掉 `tier === 'pro'` 的素材，也不显示任何会员角标。
6. **模式不记忆**：每次打开都是普通状态；操作台 `/create` 刷新仍在操作台，专业工作台 `/editor` 刷新仍在专业版。
7. **服务端给应用内页面的标题是兜底值**：`/create` 的原始 HTML 里 title 是「豆玩 DOUWAN · 豆玩 DOUWAN」，
   客户端接管后会改成「拼豆操作台 · 豆玩 DOUWAN」。要一次到位就在后端
   `internal/service/seo.go` 的 `appRouteTitle()` 里加一条 `/create` 分支。
8. **本地 AI 出图模块**（并行会话在做）本次没有动，仍未提交、未部署。
9. **首页的正文只剩原始 HTML 里有**：2026-10-26 晚按用户要求，首屏以下的
   `HomeContent`（转换步骤 / 功能 / FAQ / 分类入口）从页面上删掉了。
   服务端的 SEO 壳仍按 `src/data/seo.js` 把同样的文案写进首页**原始 HTML**
   （`seo-steps` / `seo-faq` / `seo-links` 等），爬虫读到的正文与内链没少，
   Vue 挂载后页面上看不到那段。要让正文重新出现在页面上，就把它挂回 `HomeView.vue`。
10. **预览图放大只做在电脑与平板**（≥781px）：手机端预览区限高 34~46vh 的老规矩没动
    （第 ② 步的预览区、第 ③ 步的成果预览框都是如此）。
    放大靠 CSS 覆盖画布的行内尺寸（`!important`），写法与踩过的坑见 §2「预览图为什么以前很小」——
    再改这块别用 `height:100%`，画布固有高度会把网格行顶住、百分比解析不出来、直接溢出容器。
    ⚠️ 手机端的画布宽高是两个**定值**（行内 px），`max-width` 与 `max-height` 各自独立生效，
    两者不等时画面会轻微变形；这次没动手机端，真要修得让宽高保持比例。
