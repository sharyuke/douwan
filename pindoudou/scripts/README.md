# 色板数据说明（真实品牌色卡）

`src/data/palette.js` 里的**每一个色号都对应线下可购买的真实拼豆产品**，色号可直接拿去采购。

## 内置色板

| 色板 | 色数 | 主流度 | 来源 |
| --- | ---: | --- | --- |
| MARD 291 色套装（默认） | 291 | 国内默认参考体系 | WebFEM / perler-beads `colorSystemMapping`（与 pixelbead 2026 色卡、pindou.online 291 色表逐色一致） |
| MARD 264 / 221 / 120 / 96 / 72 / 48 / 24 色套装 | 264…24 | 同上 | 同一套色号的子集，与 291 共用一份色值（色号清单取自 get-colors-from-beans） |
| COCO 全色套装 | 291 | 常见性价比品牌 | WebFEM COCO 291 色表 |
| 漫漫全色套装 | 278 | 老牌 / 图纸生态常见 | WebFEM 漫漫色表，剔除 13 个 W/ZG 兜底色号与 1 个无编号色块 |
| 盼盼全色套装 | 291 | 工具生态常见 | WebFEM 盼盼色表，291 个可确认编号全收 |
| 咪小窝全色套装 | 286 | 玩家圈常见 | WebFEM 咪小窝色表，W1–W5 与 MARD Q1–Q5 同色、暂不重复收录 |
| 优肯 Artkal C197 色 | 197 | 官方稳定/进阶常用 | Artkal 官方 RGB 色卡 PDF（C 系列，含 CE/CG/CP/CT） |
| Hama 米迪色板 | 92 | 国际经典 | beadcolors 项目实物测量值（官方色号 H01…） |
| Perler 色板 | 103 | 北美经典 | beadcolors 项目实物测量值（官方 SKU，如 80-15179） |

**漫德 MARD 是一个体系、八个套装**：24 / 48 / 72 / 96 / 120 / 221 / 264 / 291 共用同一套色号，
同一个色号在哪个套装里都是同一个色值 —— 换套餐只会多出/少掉色号，不会让同一个色号变色。
会员权益也按体系判断（免费版对漫德每个套装都给全），所以统计色号总数时**不能把八套长度相加**
（`PALETTE_TOTAL_CODES` 会去重，见 `src/lib/palettes.js`）。

## 重新生成

```bash
node scripts/build-palette.cjs            # 校验 + 写出 src/data/palette.js
node scripts/build-palette.cjs --check    # 只校验不写文件
node scripts/build-palette.cjs --offline  # 复用 scripts/.palette-cache 里的缓存
```

脚本会：下载上游数据 → 逐项交叉验证 → 自检（色号唯一 / hex 合法 / 套装嵌套）→ 写出 `src/data/palette.js`。
任一硬校验不通过就**中止构建**（不会写出半份数据）。

> 需要能访问外网的环境。若本机 DNS 被劫持导致拉取失败，可在有外网的机器上执行，再把生成的 `palette.js` 拷回来。

## 验证结果（2026-10-24 实测）

### 1. 统一口径与多源比对

国内五个体系（MARD / COCO / 漫漫 / 盼盼 / 咪小窝）的**色号与色值统一取 WebFEM 的
`perler-beads colorSystemMapping` 派生表**（`webfem.com/tools/pindou/*/colors.js`）。
换掉旧口径的原因很直接：旧版 MARD 221 用 Alfonse 版覆盖、COCO 用另一套 get-colors 值，
与独立 291 色表逐色比对时发现：

- COCO 210/291 个色号偏差 >12/255（平均 29.7，最大 152.1），`GB` 整段错位
  （GB1 旧值 `#ff4d5e`，291 表是 `#daabb3`；GB7 旧值 `#d42d7b`，291 表是 `#e2a9d2`）；
- 漫漫 34 个色号偏差 >12（最大 308.3），`D26–D36` 整段错位、`DH6` / `DH14` 错位；
- 盼盼 `1` 号与 `69` 号黑白颠倒（1 号应为白 `#feffff`，69 号应为青 `#238891`）；
- MARD 276/291 个色号与 291 色表有差异（平均单通道 5.97，最大 50），
  例如 `R6` 旧值 `#1eba93`、291 表 `#238891`；`A25` 旧值 `#fdf785`、291 表 `#ffd67d`。

现在构建脚本把下面几条做成**硬校验**（不通过就中止，不会写出半份数据）：

1. 色号集合：MARD 291 / COCO 291 / 盼盼 291 必须与 WebFEM 逐色一致；MARD 221 必须等于
   WebFEM 291 的 221 子集；
2. 套装嵌套：`24 ⊂ 48 ⊂ 72 ⊂ 96 ⊂ 120 ⊂ 221 ⊂ 291`，且同一色号跨套装色值零差异；
   264 必须完全落在 291 里（上游口径：264 不含 221 里的 `C29`，脚本打印警告并原样保留）；
3. 色号唯一、hex 合法（8 位带透明度按白底合成成 6 位）；
4. 跨品牌同色号对照：用 WebFEM 的 `mardKey` 把 COCO / 漫漫 / 盼盼 / 咪小窝 对回 MARD 291，
   偏差 ≥12/255 的色号会打印出来并警告。

### 2. 独立来源交叉校验

除 WebFEM 外，构建脚本还下载并使用以下独立数据做对照：

- **pixelbead 2026 色卡 / pindou.online 291 色表**：MARD 291 的色号集合与两者逐色一致；
- **get-colors-from-beans**：MARD 八个套装的色号清单（色值统一取 WebFEM）；
- **pindou-color-data**：COCO / 漫漫 / 盼盼 / 咪小窝 的色号清单与 `unidentified` 标记；
- **Alfonse MARD 221 官方色卡版**：221 个色号的独立对照（旧版用它覆盖，现改为只做交叉验证）；
- **beadcolors**：Hama / Perler 的实物测量值。

### 3. 不可辨认色号

上游页面里有若干色号写作 `-`（无法确认真实品牌编号），pindou-color-data 把它们规范化为
`UNKNOWN-01..04` 并标 `unidentified`。本站的处理是**直接剔除，不做猜测**：

- 盼盼：4 个无编号色块不收录，291 个可确认编号全收；
- 咪小窝：4 个无编号色块不收录；`W1–W5` 与 MARD `Q1–Q5` 同色，暂不重复收录，保留 286 色；
- 漫漫：13 个沿用 MARD `W*` / `ZG*` 的兜底色号与 1 个 `-` 不收录；上游重复的 `S4`
  按颜色拆成 `S4`（绿）/ `S7`（粉），`L7` 对应上游无编号深灰。

图纸上的色号是要拿去下单的，印一个"不知道是几号"的色号比少几个色号更糟。

### 4. 屏幕色值与实物

公开色卡给的都是**屏幕 HEX 近似值**：同一颗豆子在不同显示器、不同拍摄光线下读数都不同，
品牌批次之间也有色差。所以「色号 → 实物」能保证的是**色号本身可采购、能对上品牌色卡**；
「屏幕 HEX → 实物颜色」的零误差只能靠实体色卡或分光测色仪，任何网站都做不到。
转换算法这一侧已经做到可证明的最优：每一格都在整块色板里按 CIEDE2000 全量搜索取最近色号
（`node scripts/verify/palette-mapping.mjs` 用 8 块色板、上万格逐格核对，
另有 `pnpm verify:palette` 盯色号数据与套装嵌套）。

**关于 `H1`**：曾有第三方项目把 `H1` 当作"透明珠"的内部标记。经核对，MARD 两份独立来源都认定 `H1` 是白色（`#FFFFFF` / `#FBFBFB`，差异属上述正常范围），因此 `H1` 是正常可购买的白色豆。

**关于 Artkal `CT` 系列**：`CT01`–`CT09` 是半透明珠，官方色卡给的是带透明度的 8 位色值。脚本按"白底板上的观感"合成为 6 位色值，色号仍可正常采购。

**关于 COCO 的重色号**：291 个色号里有 2 组（`#FFFFFF`、`#FFFDF7`）是两个不同色号共用同一色值，
这是品牌自身的编号方式，**没有做合并**（合并会让其中一个色号买不到）。

## 引擎色号上限

`MAX_TARGET_COLORS = 291`，**等于最大色板长度**（漫德 MARD 291 / COCO 291 都能整块用上；
色板更小的品牌按实际色号数封顶）。它必须同时满足两条，两条都有自检盯着：

- `PACK_CAPACITY >= MAX_TARGET_COLORS`（`pnpm verify:archive` 钉住）：紧凑存档是「一格一字符」，
  字符集 548 个 → 容量 547，比任何一块色板都大（历史：90 → 255 → 547，两次都是被色板推着扩的）。
  真超过容量就退回旧格式存，解码端两种都认 —— 只是体积涨约 6 倍；
- 记忆化下标不能溢出（`pattern.js` 的 `MEMO_MAX_COLORS`）：下标存的是 `Uint16Array`。
  用 `Uint8Array` 会把 290 静默绕回 34，表现是「换了大色板之后某些格子变成别的颜色」。

注意「上限」不等于「建议值」：实测拐点在 48~64 色，引擎自己在 126 色左右就收敛了，
放到 291 是留给「先把这张图转准」的余量，不是推荐值。

## 采购建议

图纸右侧「颜色用量」面板给出的色号+数量可直接下单。同色号在不同品牌之间**不能通用**（例如 MARD 的 `H1` 与 Hama 的 `H01` 是两个不同产品），所以下单前请确认色板选择器里选的是哪个品牌。
