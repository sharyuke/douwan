# 色板数据说明（真实品牌色卡）

`src/data/palette.js` 里的**每一个色号都对应线下可购买的真实拼豆产品**，色号可直接拿去采购。

## 内置色板

| 色板 | 色数 | 主流度 | 来源 |
| --- | ---: | --- | --- |
| MARD 291 色套装（默认） | 291 | 国内默认参考体系 | 公开色卡库（get-colors-from-beans）+ 官方色卡版（Alfonse）覆盖 |
| MARD 264 / 221 / 120 / 96 / 72 / 48 / 24 色套装 | 264…24 | 同上 | 同一套色号的子集，与 291 共用一份色值 |
| COCO 全色套装 | 291 | 常见性价比品牌 | 公开色卡库（pindou-color-data 的 coco-291） |
| 漫漫全色套装 | 278 | 老牌 / 图纸生态常见 | 公开色卡库（manman-278，5 组重复色号已交叉校正） |
| 盼盼全色套装 | 285 | 工具生态常见 | 公开色卡库（panpan-289，剔除 4 个无法确认的色号） |
| 咪小窝全色套装 | 286 | 玩家圈常见 | 公开色卡库（mixiaowo-290，剔除 4 个无法确认的色号） |
| 优肯 Artkal C197 色 | 197 | 官方稳定/进阶常用 | Artkal 官方 RGB 色卡 PDF（C 系列，含 CE/CG/CP/CT） |
| Hama 米迪色板 | 92 | 国际经典 | beadcolors 项目实物测量值（官方色号 H01…） |
| Perler 色板 | 103 | 北美经典 | beadcolors 项目实物测量值（官方 SKU，如 80-15179） |

**漫德 MARD 是一个体系、八个套装**：24 / 48 / 72 / 96 / 120 / 221 / 264 / 291 共用同一套色号，
同一个色号在哪个套装里都是同一个色值 —— 换套餐只会多出/少掉色号，不会让同一个色号变色。
会员权益也按体系判断（免费版对漫德每个套装都给全），所以统计色号总数时**不能把八套长度相加**
（`PALETTE_TOTAL_CODES` 会去重，见 `src/lib/palettes.js`）。

## 重新生成

```bash
node scripts/build-palette.cjs            # 校验 + 写出 src/data/palette.js
node scripts/build-palette.cjs --check    # 只校验不写文件
node scripts/build-palette.cjs --offline  # 复用 scripts/.palette-cache 里的缓存
```

脚本会：下载上游数据 → 逐项交叉验证 → 自检（色号唯一 / hex 合法 / 套装嵌套）→ 写出 `src/data/palette.js`。
任一硬校验不通过就**中止构建**（不会写出半份数据）。

> 需要能访问外网的环境。若本机 DNS 被劫持导致拉取失败，可在有外网的机器上执行，再把生成的 `palette.js` 拷回来。

## 验证结果（2026-10 实测）

### 1. 同一体系的多来源比对

MARD 的来源 A（get-colors-from-beans 的 `get-colors.json`）与来源 B（pindou-color-data 规范化后的
`mard-291-github` / `mard-221-github`）**逐色完全一致**（291/291、221/221，零差异）——
上游规范化没有引入改动，脚本把这条钉成了硬校验。

来源 A 与来源 C（`mard-221-alfonse-doudou`，MARD 官方色卡 Alfonse 版）都是 221 个色号、色号集合完全相同：

```
完全一致 144 色 (65%)
有差异    77 色
差异色单通道偏差：平均 5.01，最大 38；偏差 >12 的仅 8 色 (10.4%)
```

**为什么会有差异**：拼豆是注塑染色件，不同批次、不同色卡版本之间本身就存在色差；两份来源分别从
不同版本的官方色卡取样，因此有 65% 完全一致、其余存在肉眼难辨的小偏差（平均单通道 5/255）。
这是行业数据的固有现状，不是数据错误。

**构建时以哪份为准**：以官方色卡版（C）为准覆盖这 221 个色号，291 相对 221 多出来的 70 个色号
只有 A/B 口径（note 字段里写明了这一点）。这样保证八个套装共用一份色值。

### 2. 套装嵌套

`24 ⊂ 48 ⊂ 72 ⊂ 96 ⊂ 120 ⊂ 221 ⊂ 291` 全部通过，且同一色号跨套装色值零差异（等于换套餐不变色）。
唯一的例外是上游自身的口径：**264 套装不含 221 套装里的 `C29`**（`264` 仍是 `291` 的子集，
缺的是 `R14–R28 / ZG1–8 / Q1 / Q3 / Q4 / C29`）。脚本会把这个差异打印成警告并原样保留。

### 3. 不可辨认色号

盼盼 289 与咪小窝 290 在上游页面里各有 4 个色号写作 `-`（无法确认真实品牌编号）。
上游把它们规范化为 `UNKNOWN-01..04` 并标 `unidentified`；**本站直接剔除**（盼盼 285、咪小窝 286）——
图纸上的色号是要拿去下单的，印一个"不知道是几号"的色号比少 4 个色号更糟。

漫漫的 5 组重复色号，上游已用 xiaoana、Zippland/perler-beads、PinDou 前端映射三份独立来源校正，
本站沿用校正后的色号。

### 4. 独立来源交叉校验（不参与构建，失败只警告）

拿另一个作者维护的换算表（Zippland/perler-beads 的「色号对应表」）验证「同一个物理颜色在各体系里的色号」：

```
漫漫   可比 277 行 · 同色 249 · 近似 4 · 明显不同 24 · 一致率 91.3%
盼盼   可比 281 行 · 同色 260 · 近似 12 · 明显不同 9 · 一致率 96.8%
咪小窝 可比 286 行 · 同色 267 · 近似 12 · 明显不同 7 · 一致率 97.6%
COCO   可比 291 行 · 同色 59 · 近似 25 · 明显不同 207 · 一致率 28.9%
```

盼盼 / 咪小窝的色值本身就与 MARD 相同（对应表按颜色换算，所以能逐色对上）；
漫漫的低一致率集中在 `C` / `D` 两个系列的编号错位上；**COCO 的一致率只有 28.9%**：
对应表的 COCO 列与本站 `coco-291` 是同一套色号命名、但色值不同（多数行属于同色系的不同深浅），
判断为该表取自另一个/更早的 COCO 色卡版本，**不作为本站 COCO 数据的依据**，仅作提示保留。
说到底，公开色卡数据无法从品牌官网逐色核对 —— 采购前请以实体色卡为准。

**关于 `H1`**：曾有第三方项目把 `H1` 当作"透明珠"的内部标记。经核对，MARD 两份独立来源都认定 `H1` 是白色（`#FFFFFF` / `#FBFBFB`，差异属上述正常范围），因此 `H1` 是正常可购买的白色豆。

**关于 Artkal `CT` 系列**：`CT01`–`CT09` 是半透明珠，官方色卡给的是带透明度的 8 位色值。脚本按"白底板上的观感"合成为 6 位色值，色号仍可正常采购。

**关于 COCO 的重色号**：291 个色号里有 2 组（`#FFFFFF`、`#FFFDF7`）是两个不同色号共用同一色值，
这是品牌自身的编号方式，**没有做合并**（合并会让其中一个色号买不到）。

## 引擎色号上限

`MAX_TARGET_COLORS = 291`，**等于最大色板长度**（漫德 MARD 291 / COCO 291 都能整块用上；
色板更小的品牌按实际色号数封顶）。它必须同时满足两条，两条都有自检盯着：

- `PACK_CAPACITY >= MAX_TARGET_COLORS`（`pnpm verify:archive` 钉住）：紧凑存档是「一格一字符」，
  字符集 548 个 → 容量 547，比任何一块色板都大（历史：90 → 255 → 547，两次都是被色板推着扩的）。
  真超过容量就退回旧格式存，解码端两种都认 —— 只是体积涨约 6 倍；
- 记忆化下标不能溢出（`pattern.js` 的 `MEMO_MAX_COLORS`）：下标存的是 `Uint16Array`。
  用 `Uint8Array` 会把 290 静默绕回 34，表现是「换了大色板之后某些格子变成别的颜色」。

注意「上限」不等于「建议值」：实测拐点在 48~64 色，引擎自己在 126 色左右就收敛了，
放到 291 是留给「先把这张图转准」的余量，不是推荐值。

## 采购建议

图纸右侧「颜色用量」面板给出的色号+数量可直接下单。同色号在不同品牌之间**不能通用**（例如 MARD 的 `H1` 与 Hama 的 `H01` 是两个不同产品），所以下单前请确认色板选择器里选的是哪个品牌。
