# 2026-11-05 深夜 钉板推荐收敛：104 够用不再给 120

用户反馈：「我发现你都是默认的推荐 120x120，优化一下，还是要根据图案的复杂程度智能推荐，
104 就够的就不要用 120，52 就够的就不要用更大的版。」

## 改法

- `src/lib/complexity.js`：120 的门槛从 0.62 提到 0.85，52 / 78 / 104 的 0.2 / 0.42 不动。
  原因写进文件头：104 → 120 只多 16 格（+15%），照片纹理在 80 格工作图上已经饱和，
  再给一块更大的板，用户认得出的东西不会变多。
- 档位文案：104「较复杂 · 照片、插画细节多」；120「极复杂 · 细节极密、纹理满布」。
- 普通照片（南瓜、猫、蒙娜丽莎、苹果、风景）现在落 104；花蕊微距 0.90、女孩抱狗 0.86
  这类极密细节才到 120。简单平涂图仍 52，人像 / 水果 / 天空仍 78，森林类 104。
- 推荐仍然取三条上限的最小值：复杂度、源图分辨率（一格至少 2 个源像素）、套餐。

## 验证

- `pnpm verify:complexity` 全过：`photo_pumpkin` 改为断言 104；逐像素噪点合成图仍断言 120。
- 本地 `audit-photo` 四视口：普通照片 → 104×104，钉板下拉「推荐」挂在 104，
  手机提示卡「推荐 1 块 104 钉板」；极密照片 → 120×120；简单图仍 52。
- 首页拖图 → 52 正常（`audit-home-upload` 四视口全过）。
- 线上复验 `node scripts/audit.cjs --url https://dw.sharyuke.com --eval-file scripts/audit-photo.js --page editor`：
  四视口全过，线上 `photoNormal` 104、`photoExtreme` 120，0 控制台错误、无横向溢出。
- 桌面 / 手机的色号滑块旧探针仍报 `colors.ok: false`，是改版前就有的问题，与推荐无关。

## 限制

- 0.85 是这次定的线。真实照片样本里 0.72~0.81 都落 104；花蕊微距 0.90、女孩抱狗 0.86
  会到 120。如果用户觉得这两类也该 104，可以再把门槛往上调（同时要改 `verify:complexity`
  的 120 锚点，保证离边界 ≥ 0.03）。
